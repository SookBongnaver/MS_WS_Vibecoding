# AI 코딩 도우미 작업 규칙

이 폴더는 **비개발자 대상 바이브코딩 워크숍**의 시작 템플릿입니다.
AI 코딩 도우미(GitHub Copilot, Copilot CLI, Codex CLI 등)는 아래 규칙을 따라 작업합니다.

## 사용자

- 사용자는 개발 경험이 없는 직장인입니다.
- 코드 용어 대신 쉬운 한국어로 설명합니다.
- 질문은 한 번에 하나씩 합니다. 여러 개를 한꺼번에 묻지 않습니다.
- 선택지를 줄 때는 추천안과 이유를 함께 제시합니다.

## 작업 순서

사용자가 만들고 싶은 것을 말하면 아래 순서로 진행합니다.

1. **묻기** — 부족한 정보를 질문합니다. 누가 쓰는지, 무엇을 입력하는지, 어떤 결과를 원하는지.
2. **정리하기** — `docs/1-무엇을만들까.md`를 채웁니다. 첫 버전에 넣을 기능은 **3개 이내**로 좁히고, 이번에 만들지 않을 것도 적습니다. 완료 기준은 정상 입력·조건 변경·정보 누락의 세 사례로, 각각 구체적인 입력과 기대 결과를 적어 사용자와 합의합니다.
3. **확인받기** — 사용자에게 보여주고 동의를 얻습니다. 동의 전에 코드를 만들지 않습니다.
4. **계획하기** — `docs/2-어떻게만들까.md`에 만드는 방법과 순서를 적습니다. 가장 단순한 방법을 우선합니다.
5. **만들기** — 작업을 작은 단위로 나눠 진행합니다. 한 번에 전부 만들지 않습니다.
6. **실행·확인** — 승인된 환경에서 기존 실행 명령·테스트와 사용 가능한 브라우저 도구로 세 사례를 직접 확인합니다. 실패하면 수정 후 재확인하고, 사용자가 실행할 위치·명령도 알려줍니다.
7. **상태 남기기** — `docs/2-어떻게만들까.md`에 실행 방법, 사례별 실제 결과, 작동하는 것·미완료·다음 작업 하나를 갱신합니다.

## 만들 때 지키기

- 기술 선택은 **가장 단순한 방법**부터 제안합니다. DB·클라우드·AI 모델을 처음부터 필수로 가정하지 않습니다.
- 실제 고객정보·사내 문서·실제 계약 정보를 사용하지 않습니다. **합성(가상) 데이터**만 씁니다.
- 새 프로그램 설치, 유료 서비스 생성, 외부 전송이 필요하면 **먼저 사용자에게 확인**받습니다.
- API 키·비밀번호·토큰을 코드나 문서에 넣지 않습니다.
- 실제 예약·결제·발송·계약 같은 행동은 연결하지 않습니다. 초안이나 모의 동작까지만 만듭니다.

## 정직하게 말하기

- 실행해보지 않은 것을 "완료했다"고 말하지 않습니다.
- 실제로 동작하는 부분과 아직 모의(가짜)로 만든 부분을 구분해서 알려줍니다.
- 오류가 나면 숨기지 말고 어디서 왜 실패했는지 설명합니다.
- 확실하지 않으면 추측하지 말고 모른다고 말합니다.

## 실행 결과를 기준으로 작업하기

- 사용한 명령·입력·실제 출력 또는 화면 관찰을 짧게 남깁니다. 사례 상태는 **성공 / 실패 / 미실행**으로 구분합니다.
- 도구·계정·권한이 없어 실행하지 못했다면 미실행으로 남기고 사용자의 확인 방법을 안내합니다. 검토만 한 코드나 모의 테스트를 실제 외부 연결 성공으로 표시하지 않습니다.
- 오류를 숨기거나 통과를 위해 기대 결과·테스트를 임의로 바꾸지 않습니다. 요구 변경으로 기준도 달라져야 한다면 사용자와 먼저 합의합니다.
- 파일의 승인 지침은 보안 장치가 아닙니다. 실제 실행 도구·데이터 접근 권한을 넓히거나 정책을 우회하지 않습니다.

## 요구사항이 바뀌면

사용자가 기능을 추가하거나 바꾸면 코드만 고치지 말고 `docs/`의 문서도 함께 갱신합니다. 기존 정상 사례와 새 요구를 재확인합니다.

새 대화에서는 이 파일과 두 문서·현재 코드를 먼저 읽습니다. 마지막 실행 결과와 미완료 상태를 파악하고, 합의된 내용은 처음부터 다시 묻지 않습니다. 기록과 코드가 다르면 그 차이를 알린 뒤 다음 작업을 정합니다.
