# 00. 워크숍 진행 방식

[처음으로](../README.md) · [다음: 환경 준비](01-environment.md)

## 목표

**내 업무에 필요한 에이전트를 자연어로 만들고, 데이터를 확인하면서 개선하는 방법을 경험합니다.**

다섯 개의 결과물을 모두 만드는 수업이 아닙니다. 공통 환경을 준비한 뒤 관심 있는 시나리오 하나를 선택합니다. 해당 가이드를 따라 기본 기능을 완성하고, 자신이 정한 요구사항을 추가합니다.

## 무엇이 에이전트인가요?

이번에 만드는 프로그램은 사용자의 요청에 맞게 AI 모델이 필요한 도구를 선택합니다.

예를 들어 캠페인 개선 요청을 받으면 다음처럼 동작합니다.

1. 분석할 기간과 목표가 없으면 먼저 질문합니다.
2. DB에서 캠페인 성과를 조회합니다.
3. 계산 도구로 성과 지표를 계산합니다.
4. 근거가 부족한 부분을 구분하고 개선안을 작성합니다.
5. 사용자가 결과 저장을 요청하면 허용된 폴더에 저장합니다.

모든 질문에 미리 정한 답변을 출력하거나, 모델 없이 정해진 작업만 순서대로 수행하는 프로그램과 구분됩니다. 도구를 선택할 수 있다고 해서 모든 시스템에 접근할 권한이 생기는 것은 아닙니다.

## 전체 진행

시간은 구성 예시이며 행사 시간·인원에 맞춰 확정합니다. 계정 승인·모델 할당량 확보·설치 대기는 실습 시간과 분리합니다.

| 구간 | 활동 | 참가자의 역할 |
|---|---|---|
| 사전 준비 | Foundry·SQL·선택한 코딩 도구 구성 | 가이드에 따라 접속하고 연결 확인 |
| 공통 시작 | 완성 예시와 제작 방식 이해 | 제작 도구와 실행 프로그램 구분 |
| 시나리오 선택 | 공개 사업 맥락과 준비된 과제 살펴보기 | 해결할 문제 한 문장으로 작성 |
| 기본 따라하기 | 단계별 프롬프트로 에이전트 제작 | 실행 결과를 확인하며 다음 단계 진행 |
| 논의 | 동료가 사용자 역할로 질문 | 부족한 조건·불명확한 답변 발견 |
| 개선 | 자연어로 변경을 요청하고 재실행 | 추가 요구사항 하나 이상 반영 |
| 공유 | 작동 장면과 개선한 점 설명 | 잘된 점·한계·후속 과제 공유 |

## 시나리오를 고르는 방법

기술적으로 멋있어 보이는 주제보다 **내가 결과의 좋고 나쁨을 판단할 수 있는 주제**를 고르세요.

- 고객 경험과 서비스 제안에 관심 있다면: 워커힐
- 거래 조건과 고객 안내에 관심 있다면: 민팃
- 현장 운영과 접수 프로세스에 관심 있다면: SK스피드메이트
- 숫자와 마케팅 성과에 관심 있다면: 인크로스
- 사업개발과 파트너 비교에 관심 있다면: SK인텔릭스

직무에 꼭 일치할 필요는 없습니다. 선택한 주제를 통해 공통 제작 방식을 익힌 뒤 본인 업무에 응용합니다.

## 매 단계의 진행 습관

1. 요청할 내용을 읽고 필요한 조건을 이해합니다.
2. 가이드의 프롬프트를 **선택한 코딩 도우미**에 입력합니다.
3. 도우미가 변경하려는 파일·실행 명령을 확인합니다.
4. 에이전트를 **별도 터미널**에서 실행합니다.
5. 도구 호출과 결과를 확인하고, 기준에 맞으면 다음 단계로 갑니다.

코딩 도우미가 코드를 만들었다고 말하는 것과 에이전트가 실제로 작동하는 것은 다릅니다. 생성 후에는 반드시 직접 실행합니다.

## 이번에 하지 않는 것

- 다섯 시나리오 전체 구현
- 운영용 사내 플랫폼 구축
- 실제 고객 데이터 적재
- 실제 예약·결제·광고 집행 등 업무 변경
- 대규모 다중 에이전트 구성

웹 화면은 기본 에이전트가 완성된 뒤 선택적으로 추가할 수 있습니다. 화면 제작 때문에 DB 조회와 도구 실행을 건너뛰지 않습니다.
