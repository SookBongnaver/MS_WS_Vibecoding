# 03. 논의하고 개선하기

[처음으로](../README.md)

## Step 1. 기본 동작 설명

선택한 시나리오의 기본 에이전트를 실행하고 다음을 짚어봅니다.

- 사용자가 어떤 요청을 했나요?
- 어떤 DB 데이터와 도구를 사용했나요?
- 무엇을 계산했고 어떤 근거를 제시했나요?
- 사람이 확인해야 할 부분은 무엇인가요?

## Step 2. 동료가 사용자 역할로 요청

다른 참가자에게 코드를 설명하기 전에 에이전트를 사용해보게 합니다. 기본 예시를 그대로 반복하기보다 조건 하나를 바꿔보세요.

| 변경 | 살펴볼 동작 |
|---|---|
| 조건을 일부 생략 | 필요한 질문을 하는가 |
| 데이터에 없는 ID 사용 | 없는 사실을 만들어내지 않는가 |
| 예산·기간·우선순위 변경 | 실제 재조회·재계산하는가 |
| 만족하는 후보가 없음 | 불가능한 이유와 바꿀 조건을 설명하는가 |
| 실제 예약·발송·집행 요청 | 초안 범위를 넘어 실행하지 않는가 |

동료에게 받은 피드백은 **불편했던 점 / 기대한 동작 / 실제 동작**으로 기록합니다.

## Step 3. 개선할 한 가지 선택

프롬프트 예시입니다. 대괄호 부분을 본인의 피드백으로 바꿉니다.

**선택한 코딩 도우미에 입력**

```text
현재 에이전트를 동료가 사용한 결과 다음 문제가 있었어.

사용자 요청: [실제로 입력한 요청]
기대한 동작: [기대]
실제 동작: [관찰한 결과]

관련 코드를 읽고 원인을 설명한 뒤 수정해줘.
모델 답변 문구만 바꾸지 말고 필요한 도구·검증 로직도 고쳐줘.
기존 정상 사례가 유지되는지 확인하고
같은 문제가 다시 발생하지 않도록 확인 방법을 남겨줘.
DB 조회 권한과 파일 저장 범위는 넓히지 마.
```

## Step 4. 다시 실행

실행 프로그램을 재시작하거나 필요한 변경을 반영한 후 동일한 질문을 다시 입력합니다.

**확인:** 수정 전 실패했던 상황뿐 아니라 기본 정상 요청도 여전히 동작합니다. 답변 문구의 우연한 변화만으로 개선됐다고 판단하지 않습니다.

## Step 5. 선택 확장

기본 기능이 동작하면 아래 중 필요한 확장을 선택합니다.

- 결과를 쉽게 비교하는 표·차트·간단한 웹 화면
- 누락 정보에 대한 추가 질문
- 근거 ID와 데이터 시점 표시
- 반복 사용을 위한 출력 형식
- 다른 사용자를 위한 도움말

새 도구·데이터 연결은 권한과 구현 부담이 늘어납니다. 먼저 제공된 데이터 안에서 기능을 확장합니다.

## Step 6. 결과 공유

공유할 내용은 다음과 같습니다. 투표나 심사 기준이 아니라 제작 경험을 설명하기 위한 순서입니다.

1. 누구의 어떤 업무를 돕는 에이전트인가?
2. 실제 실행했을 때 무엇을 조회하고 어떤 결과를 만드는가?
3. 기본 실습에서 무엇을 추가·개선했는가?
4. 여전히 불확실하거나 사람이 확인해야 하는 부분은 무엇인가?

## Step 7. 실습 정리

- 코드와 교육용 결과물을 보관합니다.
- 로컬 설정·토큰·비밀번호가 Git에 포함되지 않았는지 확인합니다.
- 본인이 만든 실습 리소스 목록을 확인합니다.
- 운영자 안내에 따라 본인 전용 리소스만 정리합니다. 공동 모델·서버·DB는 임의로 삭제하지 않습니다.
- 단순히 Python이나 코딩 도구를 종료해도 클라우드 리소스 비용이 모두 중단되는 것은 아닙니다.
