# 지정된 코딩 도구 설치·로그인

[워크숍으로 돌아가기](../README.md)

도구 비교·고객 환경 준비는 README에 정의되어 있습니다. **강사가 지정한 경로 하나만** 적용하며 참가자 계정의 사용 권한·조직 정책·잔여 사용량을 확인합니다.

## GitHub Copilot — VS Code

1. [VS Code](https://code.visualstudio.com/)를 설치합니다.
2. [공식 설정 안내](https://code.visualstudio.com/docs/copilot/setup)에 따라 Copilot을 설정하고 지정된 GitHub 계정으로 로그인합니다.
3. 새 작업 폴더를 **File → Open Folder**로 엽니다.
4. Chat에서 **Agent 모드**를 선택합니다. 모드가 보이지 않으면 버전·플랜·조직 정책을 확인합니다.
5. README의 첫 요청을 입력해 응답과 프로젝트 접근을 확인합니다.

## GitHub Copilot CLI

1. [공식 CLI 설치 안내](https://docs.github.com/en/copilot/how-tos/copilot-cli/set-up-copilot-cli/install-copilot-cli)에서 고객 PC에 맞는 설치 방법을 따릅니다.
2. 새 작업 폴더에서 터미널을 엽니다.
3. 아래 명령을 실행하고 로그인 안내를 따릅니다.

```powershell
copilot
```

4. 강사가 지정한 GitHub 계정을 사용하고 README의 첫 요청을 입력합니다.

CLI 설치만으로 Copilot 사용 권한이 생기지는 않습니다. [플랜과 제공 기능](https://docs.github.com/en/copilot/get-started/plans)을 확인합니다.

## Codex CLI

1. [공식 CLI 안내](https://developers.openai.com/codex/cli)와 [Windows 안내](https://developers.openai.com/codex/windows)를 확인합니다.
2. npm 설치 방식을 사용하는 경우 지원되는 Node.js를 먼저 준비하고 다음 명령을 실행합니다.

```powershell
npm.cmd install -g @openai/codex
```

3. 새 작업 폴더의 터미널에서 실행합니다.

```powershell
codex
```

4. 고객이 승인한 계정·인증 방식으로 로그인하고 README의 첫 요청을 입력합니다. API 인증을 사용하는 경우에도 키를 교재·대화·저장소에 넣지 않습니다.

## 환경 사전 점검

**목적:** 설치 목록이 아니라 실제 참가자 계정·PC·네트워크에서 작업이 가능한지 확인합니다. 공통 점검과 선택한 구현의 실행 점검을 분리하며, 모든 참가자에게 Python·Node.js·Foundry·DB를 요구하지 않습니다.

<a id="common-readiness"></a>

### 1. 공통 점검 — 프로젝트 복사 및 로그인 후

| 점검 | 수행 방법 | 통과 기준 |
|---|---|---|
| 계정·사용 권한 | 지정 도구에 로그인하고 짧은 제작 요청 입력 | 실제 응답 수신; 계정·정책·사용량 오류 없음 |
| 프로젝트 접근 | 복사한 `starter` 폴더를 열고 `AGENTS.md`와 `docs` 문서 2개 읽기 요청 | 실제 파일 내용을 요약; 다른 업무 폴더를 참조하지 않음 |
| 파일 생성·수정 | 아래 프롬프트로 점검용 파일 작성 | 파일을 직접 열어 내용이 요청대로 바뀌었는지 확인 |
| 작업 범위·승인 | 파일 변경·명령 실행 권한이 제한된 범위인지 확인 | 요청하지 않은 설치·외부 연결·기존 파일 변경 없음 |

**점검 프롬프트**

```text
현재 프로젝트의 AGENTS.md와 docs 문서 2개를 읽고 파일명을 알려줘. 환경 확인을 위해 .workshop-ready.txt에 READY를 기록한 다음 두 번째 줄에 EDIT_OK를 추가해줘. 같은 파일이 이미 있으면 덮어쓰지 말고 중단해줘. 다른 파일 변경·설치·클라우드 호출은 하지 마. 완료 후 파일을 다시 읽어 실제 내용을 확인하고, 내가 직접 열어 확인할 위치를 알려줘.
```

**기대 결과:** `.workshop-ready.txt`에 `READY`, `EDIT_OK` 두 줄이 존재합니다. 이는 코딩 도구의 파일 접근·편집만 확인하며, 앱 실행·모델·DB 연결의 성공을 의미하지 않습니다. 확인 후 참가자가 점검용 파일 하나만 삭제합니다.

### 2. 실행 점검 — 구현 방식·연결 결정 후

| 선택한 구성 | 점검 | 통과 기준 |
|---|---|---|
| 정적 웹앱 | 안내된 방식으로 페이지 열기 | 화면과 첫 입력·결과 동작 확인 |
| Python·Node.js 등 런타임 | 해당 프로젝트가 요구하는 버전·의존성 확인 후 실행 | 실제 프로세스·로컬 주소 또는 결과 파일 확인 |
| 외부 모델·공개 API·DB | 승인된 대상에 최소 테스트 요청 또는 읽기 조회 | 정상 응답 수신; 인증·접근·사용량 조건 확인 |

외부 연결은 추가 비용·전송 범위를 승인받은 후 확인합니다. 모델·API 응답 원문에 비밀 값이나 개인정보가 있으면 기록하지 않습니다. 런타임 설치·네트워크·권한 문제와 제품 코드 오류를 구분하고, 코드 오류를 해결하기 위해 재설치나 권한 확대를 반복하지 않습니다.

### 결과 기록

기존 `docs/2-어떻게만들까.md`에 상태와 차단 원인만 기록합니다. **통과 / 실패 / 미점검 / 해당 없음**을 구분하고, 미점검을 성공으로 처리하지 않습니다. 공통 점검이 실패하면 강사·고객 IT가 원인을 해결하며, 선택 연결이 미확보된 경우 해당 기능을 보류하거나 승인된 대안으로 범위를 조정합니다.

실제 화면은 제품 버전에 따라 달라질 수 있습니다. 이 문서에는 아직 코딩 도구별 실제 실행 스크린샷이 포함돼 있지 않습니다.
