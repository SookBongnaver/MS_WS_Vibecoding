# 제공 환경 접속 및 MS 사전 점검

[워크숍으로 돌아가기](../README.md)

MS가 고객과 합의한 코딩 도구·기본 런타임·프로젝트를 준비하는 제공형 실습 기준입니다. 참가자는 안내된 환경에 접속하며 도구 설치·라이선스 선정·초기 클라우드 구성은 수행하지 않습니다. 아래 운영 절차는 준비 기준이며 이 저장소가 실제 접속 환경이나 이용권을 자동 제공한다는 의미는 아닙니다.

## 참가자 접속 절차

1. MS 실습 운영 담당이 제공한 주소 또는 접속 경로를 엽니다.
2. 본인 계정으로 인증하고 배정된 프로젝트를 확인합니다.
3. 안내된 코딩 도구를 열고 아래 공통 점검을 수행합니다.
4. 인증·프로젝트·명령 실행 오류는 MS 실습 운영 담당에게 전달합니다. 임의 설치·권한 확대·다른 계정 공유로 해결하지 않습니다.

**인증 경계:** Azure Entra 로그인과 코딩 도구 인증·사용 권한은 구분합니다. MS가 사전 구성한 계정 연계에 따라 추가 로그인이 없을 수도 있지만, Azure 로그인만으로 모든 코딩 도구를 사용할 수 있다고 보장하지 않습니다. 필요한 추가 본인 인증·동의는 실습 전 안내합니다.

## MS 운영 담당: 도구별 사전 구성

다음 절차는 참가자용 설치 과제가 아니라 **MS가 제공 환경에 적용할 준비 절차**입니다. 고객 담당자는 계정·라이선스·정책을 승인하며, MS는 선택 도구의 지원 환경과 실제 사용 권한을 확인합니다.

### GitHub Copilot — VS Code

1. 제공 환경에 [VS Code](https://code.visualstudio.com/)와 필요한 확장을 준비합니다.
2. [공식 설정 안내](https://code.visualstudio.com/docs/copilot/setup)에 따라 Copilot을 설정하고 참가자 본인이 승인된 계정으로 인증할 경로를 확인합니다.
3. 개인별 작업 폴더에 이 저장소의 `starter` 전체를 배치하고 프로젝트를 엽니다. 기존 프로젝트는 덮어쓰지 않습니다.
4. Chat에서 **Agent 모드**를 선택합니다. 모드가 보이지 않으면 버전·플랜·조직 정책을 확인합니다.
5. README의 첫 요청을 입력해 응답과 프로젝트 접근을 확인합니다.

### GitHub Copilot CLI

1. [공식 CLI 설치 안내](https://docs.github.com/en/copilot/how-tos/copilot-cli/set-up-copilot-cli/install-copilot-cli)에 따라 제공 환경에 사전 설치합니다.
2. 새 작업 폴더에서 터미널을 엽니다.
3. 아래 명령을 실행하고 로그인 안내를 따릅니다.

```powershell
copilot
```

4. 참가자 본인이 고객이 승인한 GitHub 계정으로 인증하고 README의 첫 요청을 실행할 수 있는지 확인합니다.

CLI 설치만으로 Copilot 사용 권한이 생기지는 않습니다. [플랜과 제공 기능](https://docs.github.com/en/copilot/get-started/plans)을 확인합니다.

### Codex CLI

1. [공식 CLI 안내](https://developers.openai.com/codex/cli)와 [Windows 안내](https://developers.openai.com/codex/windows)를 확인합니다.
2. npm 설치 방식을 사용하는 경우 MS가 제공 환경에 지원되는 Node.js를 준비하고 다음 명령을 실행합니다.

```powershell
npm.cmd install -g @openai/codex
```

3. 새 작업 폴더의 터미널에서 실행합니다.

```powershell
codex
```

4. 고객이 승인한 계정·인증 방식에서 첫 요청이 동작하는지 참가자 본인 인증으로 확인합니다. API 인증을 사용하는 경우에도 키를 교재·대화·저장소에 넣지 않습니다.

## 환경 사전 점검

**목적:** MS가 제공할 환경이 고객 접속 경로·참가자 계정에서 실제로 동작하는지 확인합니다. MS 사전 리허설과 참가자의 접속·편집 확인을 구분하며, 필요한 런타임·드라이버·연결은 MS가 준비합니다.

<a id="common-readiness"></a>

### 1. 공통 점검 — MS 사전 리허설 및 참가자 접속 확인

| 점검 | MS 준비·지원 | 참가자 확인 | 통과 기준 |
|---|---|---|---|
| 계정·사용 권한 | 고객과 이용권·인증 경로 사전 확정 | 본인 인증 후 짧은 제작 요청 입력 | 실제 응답 수신; 계정·정책·사용량 오류 없음 |
| 프로젝트 접근 | 개인별 `starter` 배치·접근 범위 설정 | `AGENTS.md`와 `docs` 문서 2개 읽기 요청 | 실제 파일 내용을 요약; 다른 업무 폴더를 참조하지 않음 |
| 파일 생성·수정 | 작업 폴더 쓰기 권한·복구 방법 준비 | 아래 점검용 파일 작성 요청·내용 확인 | 요청한 두 줄이 기록됨 |
| 작업 범위·승인 | 도구 실행 권한과 승인 경계 설정 | 요청한 범위의 작업인지 확인 | 요청하지 않은 설치·외부 연결·기존 파일 변경 없음 |

**점검 프롬프트**

```text
현재 프로젝트의 AGENTS.md와 docs 문서 2개를 읽고 파일명을 알려줘. 환경 확인을 위해 .workshop-ready.txt에 READY를 기록한 다음 두 번째 줄에 EDIT_OK를 추가해줘. 같은 파일이 이미 있으면 덮어쓰지 말고 중단해줘. 다른 파일 변경·설치·클라우드 호출은 하지 마. 완료 후 파일을 다시 읽어 실제 내용을 확인하고, 내가 직접 열어 확인할 위치를 알려줘.
```

**기대 결과:** `.workshop-ready.txt`에 `READY`, `EDIT_OK` 두 줄이 존재합니다. 이는 코딩 도구의 파일 접근·편집만 확인하며, 앱 실행·모델·DB 연결의 성공을 의미하지 않습니다. 확인 후 참가자가 점검용 파일 하나만 삭제합니다.

### 2. 실행 점검 — MS가 지원하는 구현·연결 경로

| 선택한 구성 | 점검 | 통과 기준 |
|---|---|---|
| 정적 웹앱 | 안내된 방식으로 페이지 열기 | 화면과 첫 입력·결과 동작 확인 |
| Python·Node.js 등 런타임 | 해당 프로젝트가 요구하는 버전·의존성 확인 후 실행 | 실제 프로세스·로컬 주소 또는 결과 파일 확인 |
| 외부 모델·공개 API·DB | 승인된 대상에 최소 테스트 요청 또는 읽기 조회 | 정상 응답 수신; 인증·접근·사용량 조건 확인 |

선택한 도구의 기본 실행 환경은 MS가 사전 점검하며, 참가자 요구에 따라 추가되는 런타임·모델·DB는 고객 승인 범위에서 MS가 구성을 지원합니다. 외부 연결은 추가 비용·전송 범위를 승인받은 후 확인합니다. 모델·API 응답의 비밀 값·개인정보는 기록하지 않습니다. 제품 코드 오류와 환경·권한 문제를 구분합니다.

### 결과 기록

기존 `docs/2-어떻게만들까.md`에 상태와 차단 원인만 기록합니다. **통과 / 실패 / 미점검 / 해당 없음**을 구분하고, 미점검을 성공으로 처리하지 않습니다. 제공 환경 장애는 MS 실습 운영 담당이, 고객 계정·정책 문제는 고객 IT 담당이 조치합니다. 선택 연결이 미확보된 경우 해당 기능을 보류하거나 승인된 대안으로 범위를 조정합니다.

실제 화면은 제품 버전에 따라 달라질 수 있습니다. 이 문서에는 아직 코딩 도구별 실제 실행 스크린샷이 포함돼 있지 않습니다.
